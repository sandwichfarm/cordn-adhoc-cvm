# Quick Task 260802-jj8: Participant emoji shortcuts and persistent message reactions

<objective>
Give hosts and guests the same visible emoji composer shortcuts and let every connected participant react to any visible message with persistent, synchronized, aggregated reaction state.

Purpose: The current host and member renderers duplicate message/composer behavior, and the MLS room model persists only ordinary messages. Reactions must cross the same authenticated encrypted channel without creating a second store or making old cached conversations unreadable.
Output: A backward-compatible reaction wire/storage projection, host and guest reaction controls, composer shortcut parity, and focused unit/browser regression coverage.
</objective>

<interfaces>
- `ChatEnvelope` is currently the signed plaintext carried inside an MLS application message. `signChatEnvelope`, `encryptMessage`, and `decryptMessage` are the authoritative authentication/encryption boundary; extend this contract instead of adding a coordinator method.
- `ChatRoomSession.send(content)` signs an envelope, advances `stateBase64`, appends an optimistic item, queues `{ id, opaqueBase64 }`, persists, emits, and calls the existing sync loop. Reaction mutations must use the same exclusive operation and delivery order.
- `ChatRoomSession.flushPending` posts queued opaque messages and `pullMessages` consumes coordinator cursors in order. Reaction events must advance MLS state and `lastCursor` even when their target is unavailable or their projection is ignored.
- `StoredRoom.version` is `1`, with `messages`, `pending`, and `lastCursor` persisted under the existing `cordn-adhoc-chat-room:v2` namespace. Treat reaction state as an optional backward-compatible field and normalize absence to an empty projection; do not reject an otherwise valid cached room.
- `HostWorkspace.svelte` renders hosted-room messages/composer through `host-message-list`; `ChatRoute.svelte` renders joined/cached messages/composer through `guest-message-list`. Both already use the shortcuts `👍`, `❤️`, `😂`, `🎉`, `👋`, `✨`; expose one canonical exported tuple and keep these exact choices for composer and reaction controls.
- Both components clone `session.room.messages` and `pending` in their subscription update paths. Clone the reaction projection there as well so Svelte runes rerender counts and viewer state after optimistic changes and remote sync.
- The working tree already contains overlapping edits in both components, `room-store.ts`, and `phase-one.spec.ts`. Preserve those edits and make scoped changes around the current message/composer/session code; do not reset, revert, or replace unrelated work.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Participant UI -> signed MLS envelope | A local identity chooses the target, emoji, and desired state that become authenticated room data. |
| Remote MLS plaintext -> reaction projection | A group member can send malformed, replayed, forged-sender, or unknown-target mutations to every participant. |
| Persisted localStorage -> cached chat UI | Missing or tampered optional reaction data must not erase valid offline messages or enable writes without a live signer/session. |
