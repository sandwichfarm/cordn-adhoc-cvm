# Quick Task 260802-f3u: In-session invite redemption

<objective>
Let a running host paste an invite link or scan its QR payload from the current SPA shell, join the referenced remote room in-place, and keep the host's local coordinator alive.

Purpose: Hosts already have the complete parsing, remote join, persistence, and history-navigation machinery, but no in-session way to feed another host's invite into it.
Output: A shared invite-redemption dialog, automatic anonymous fallback for explicit in-session redemption, and end-to-end regression coverage.
</objective>

<interfaces>
- `WorkspaceNav` already receives `onNavigate(href: string)` from both `HostWorkspace` and `ChatRoute`; keep redemption in this shared shell instead of adding coordinator lifecycle ownership elsewhere.
- `App.navigate` rewrites external `/chat/...` URLs onto `window.location.origin` and uses `history.pushState`; pass it a validated canonical URL rather than assigning `window.location`.
- `parseInviteUrl(value)` is the authoritative validation boundary for group id, coordinator nprofile/relay hints, web origins, invite capability, and display-safe host metadata.
- `createSameShellChatHref(window.location.origin, invite)` preserves the parsed remote coordinator target while making the route local to the current SPA shell.
- `ChatRoute.join` already calls `createJoiningRoom`, whose success stores the join request, coordinator metadata, room state, and then attaches a `ChatRoomSession`.
- `HostWorkspace` teardown stops only its selected room session. Do not call `coordinator.stop`, `coordinator.restart`, or otherwise move coordinator ownership out of the global `coordinatorStore`.
</interfaces>

  <behavior>
    - Paste path: with Host A and Host B coordinators running against the mock relay, B pastes A's invite, stays in the same document, automatically joins A's room, and gets a persisted non-host room keyed by A's coordinator pubkey.
    - Runtime invariant: B can return through the SPA navigation to the workspace and still sees its own coordinator as running; a window sentinel created before redemption survives throughout.
    - Validation: malformed or non-invite text shows an actionable error, performs no navigation, and creates no room record.
    - Scan path: a mocked QR `BarcodeDetector` result is routed through the same redemption function as pasted text and the acquired video track is stopped after success.
    - Camera lifecycle: closing the scanner with no result stops all tracks and cancels detection; rejected permission, missing media support, or missing QR detection support shows a recoverable message while paste redemption stays enabled.
  </behavior>
  <action>
Write the Playwright scenarios first using the existing `configureMockRelay`, `createRoom`, invite-link, and multi-context patterns. Use a Host A context to create a real auto-approved room and a Host B context with its own running coordinator. Set a document sentinel before B redeems, paste an invite whose URL origin differs from B's shell origin, and assert the resulting URL is on B's origin, the chat composer becomes available, the room is present under the existing `cordn-adhoc-chat-room:v2` storage namespace with A's coordinator pubkey, and B's coordinator is still `running` after SPA navigation back to `/`. Mock `navigator.mediaDevices.getUserMedia` and `BarcodeDetector` with `addInitScript` for deterministic scan tests; expose track-stop and detection counters on `window` so success and cancel cleanup are asserted without real hardware.

Create `InviteRedeemer.svelte` as an accessible trigger/dialog owned by the shared navigation. Keep one `redeem(rawValue)` boundary for paste and scan: trim the input, call `parseInviteUrl`, reject `null` without leaving the dialog, convert valid data with `createSameShellChatHref(window.location.origin, invite)`, add the explicit `autojoin=1` query flag, stop the scanner, close the dialog, and call the supplied `onNavigate`. Never forward the raw pasted/scanned URL to navigation. Disable duplicate submissions while handoff is in progress and reset errors when the user retries.

Implement camera scanning without a new dependency: feature-detect `navigator.mediaDevices.getUserMedia` and `globalThis.BarcodeDetector`, request video only with an environment-facing preference, attach the stream to a muted inline video, and inspect `qr_code` detections until a payload is found. Provide precise messages for permission denial, no camera, unavailable scanning support, and invalid QR contents. Centralize cleanup so dialog close, Escape, scan success, failed camera setup after partial acquisition, and component destruction cancel animation/detection work, stop every `MediaStreamTrack`, and clear `video.srcObject`; guard asynchronous detector completions from acting after closure.

Render the new control from `WorkspaceNav` beside the existing room navigation so it is present when `showRoomBrowser` is false in `HostWorkspace` and when a user is already inside `ChatRoute`. Preserve the current room switcher, focus behavior, responsive layout, and server-online notice behavior.

Extend `ChatRoute`'s existing `autojoin=1` mount branch only when no stored room exists: set the join name from `userProfileStore.displayName`, use `userProfileStore.activeSigner` when available, and otherwise invoke the existing anonymous join routine so ordinary running hosts can redeem without first connecting NIP-07/NIP-46. Keep all registration, capability validation, persistence, error display, and session attachment in the current `join`/`createJoiningRoom` path; do not introduce a parallel room record or coordinator client.

## Trust Boundaries

|----------|-------------|
