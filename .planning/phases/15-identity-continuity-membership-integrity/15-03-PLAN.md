## Scope Cohesion Decision

Keep this as one three-task plan despite the ten-file aggregate. The files implement one irreversible privacy transaction across store, local room/session authority, its sole UI entry point, and objective evidence; four of the ten files are tests, and no task owns more than five files. Splitting modal/UI from retirement would duplicate `user-profile.svelte.ts` and browser-test ownership across sequential plans and permit an executable intermediate state where the approved confirmation surface can invoke an incomplete privacy boundary. The current decomposition is therefore safer and remains within the locked phase scope.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → identity/room transaction | Tampered/corrupt records affect recovery, impact, rollback, and retirement. |
| signer → stored `stablePubkey` | Only the signer that owns immutable membership may be retired/attached. |
| live session → rotation transaction | In-flight writes/signatures can race local authority removal. |
| composite room selector → retirement | Same room IDs across coordinators must remain isolated. |
| secret-bearing runtime → UI/log/test output | Rotation/recovery must not disclose old, corrupt, staged, or new secrets. |
