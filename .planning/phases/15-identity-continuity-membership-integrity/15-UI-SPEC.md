## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Rotate identity` |
| Empty state heading | `No local room memberships` |
| Empty state body | `This identity has no locally stored room access to remove.` |
| Error state | `Unable to rotate your identity. Your current identity and local room access are unchanged. Try again.` |
| Destructive confirmation | `Rotate local identity?` — `This creates a new device-local identity. Your local room memberships on this device will be removed, and you’ll need a new invite before you can send in those rooms again. This does not delete coordinator-hosted room data for other participants.` |

Use `Rotate identity…` for the initiating profile-menu action and `Keep current identity` for its non-destructive dismissal. The impact line is count-aware and does not list room names: `No local room memberships will be removed.`, `1 local room membership will be removed.`, or `{n} local room memberships will be removed.` Never claim that cached history is deleted or that coordinator-hosted data is destroyed.

Corrupt-identity recovery copy is distinct and must never silently create a replacement: title `Recover local identity`; body `Saved local identity data on this device could not be verified. Create a new device-local identity to continue. Local room access will be removed, and new invites are required before sending to those rooms again.`; primary action `Create new identity`.

## Phase 15 Surface and Interaction Contract

### Component inventory

| Surface | Contract |
|---------|----------|
| Existing `UserProfile` trigger and menu | Keep the compact avatar/name/auth-label trigger in the existing header location. In anonymous mode, append the device-local identity explanation and `Rotate identity…` to the existing anonymous profile section, below the display-name control and before external signer-connect controls. Do not add another menu section, navigation item, profile page, or status indicator. |
| New `IdentityRotationDialog` | Implement with the same native `<dialog>` structure, dark terminal surface, backdrop, header/body/footer layout, busy/error handling, and focus behavior as `RoomRemovalDialog`. It has `confirm` and non-dismissable `recovery` variants; it is not a generic alert or browser `confirm()`. |
| Existing identity presentation | The menu header remains the sole visual identity summary: generated avatar, display name, shortened public key, and `local` auth chip. On ordinary reload it must appear only after the durable identity is known, with no `anon`, blank key, or coordinator-key flash. |

### Normal identity state

In anonymous mode, the existing local-profile help text must state that the generated avatar and identity are device-local and persist in this browser. It must not describe the coordinator key as the user's identity. The public-key summary is presentational only; do not add copy/export controls or display a full secret/key value.

Selecting `Rotate identity…` keeps the profile menu’s current context but opens the modal confirmation above its scrim. The modal kicker is `Privacy boundary`; dialog title is `Rotate local identity?`; it presents the count-aware membership impact and the coordinator-hosted-data clarification before the user can confirm. The default focus is `Keep current identity`, preventing an accidental destructive Enter keypress.

On confirmation, disable every dialog action, suppress Escape/backdrop dismissal, change the confirm label to `Rotating…`, and expose that busy state through an `aria-live="polite"` status. Once complete, close both dialog and menu, update the header avatar/public-key summary atomically, and announce exactly `Identity rotated. Local room access was removed.` in a visually hidden polite live region. Do not show a toast, banner, room-by-room removal list, or redundant status card.

If rotation fails, keep the dialog open and restore controls. Render the documented error in the dialog body with `role="alert"`; do not change the displayed identity, avatar, membership count, or visible room state.

### Corrupt persisted identity recovery

When durable anonymous identity material is missing, malformed, wrong-length, or otherwise fails validation, do not generate a fresh identity during boot and do not display a misleading anonymous profile. Open the `recovery` dialog before an anonymous identity-dependent workspace can be used. It has the documented recovery copy, no passive backdrop/Escape dismissal, and only `Create new identity` after the user’s explicit consent. Its busy and error behavior matches confirmation, and it uses the same membership/access wording rather than promising cached-history deletion.

### Accessibility and responsive behavior

- The menu trigger remains a real button with an accurate expanded state and `aria-haspopup="dialog"`; `Rotate identity…` is keyboard reachable in the normal menu order.
- Each dialog uses `aria-labelledby` and `aria-describedby`, traps focus through native modal behavior, returns focus to the user-menu trigger after cancel/error, and closes only when a non-busy user requests cancellation.
- The dialog uses `width: min(29rem, calc(100vw - 1rem))`, `max-height: calc(100dvh - 1rem)`, and scrolls only its body. Long display names and key summaries ellipsize rather than widening the header; explanatory copy wraps at word boundaries.
- No new animation is introduced. Respect reduced motion by retaining the existing static dialog/menu transitions (none required) and never use motion to communicate loss of access or completion.
- Maintain current high-contrast terminal colors and visible focus; do not use color alone to indicate destructive state—destructive copy and button labels identify it in text.

### Explicit non-goals

Do not change authenticated NIP-07/NIP-46 flows, the header brand lockup, room navigation, conversation rendering, or coordinator lifecycle controls. Rotation is anonymous/local only; authenticated identity controls never display the rotate action.

## UI Considerations

> Populated by the ui-phase UI-consideration probe. Empty-state and error-state copy is canonical in the Copywriting Contract above; these rows define state behavior without duplicating it.

Applicable state considerations resolved: 5 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Membership-impact summary | ✅ covered | A zero-membership identity renders the documented `No local room memberships` heading and body; it does not render an empty room list. |
| loading | Confirm and recovery dialogs | ✅ covered | During rotation/recovery, every action is disabled, the primary action reads `Rotating…` or `Creating…`, and a polite live status communicates progress. |
| error | Confirm and recovery dialogs | ✅ covered | A failed action keeps the modal open, shows the documented actionable error with `role="alert"`, and leaves the current identity and local access unchanged. |
| zero-one-many | Membership-impact summary | ✅ covered | The scalar impact copy handles zero, singular, and plural memberships without exposing room names or adding a redundant collection surface. |
| long-text | Profile-menu identity summary and dialog copy | ✅ covered | The pubkey uses the fixed `8…6` summary; display names ellipsize; descriptive copy wraps without horizontal overflow. |
| loading | Delayed rotation completion | 🧪 backstop | Playwright holds rotation in flight and proves disabled controls, modal persistence, and no premature avatar/key/session change; a completion test proves the atomic replacement after success. |
