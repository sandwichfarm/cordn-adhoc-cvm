<decision_trace>
D-01: Persist one strictly validated, versioned 32-byte anonymous secret and never reuse the coordinator key.
D-02: UserProfileStore owns/exposes the anonymous signer; the display name/profile remains separate.
D-03: Present-but-corrupt credential data fails closed into explicit recovery rather than silent rotation.
D-04: Anonymous room authority will consume this signer and must prove signer pubkey equals stablePubkey.
D-05: NIP-07 and NIP-46 remain isolated from anonymous persistence and rotation.
D-06: Anonymous-only rotation requires contextual confirmation.
D-07: Matching live/local authority is retired before replacement identity exposure.
D-08: Rotation removes local authority, preserves cached history/hosted group data, and requires a fresh invite.
D-09: Room identity is always (coordinatorPubkey, roomId).
D-10: Verified v2 targets win; aliases are removed only after composite read-back; legacy room keys never seed global identity.
</decision_trace>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → identity/room parsers | Attacker-, extension-, prior-version-, or corruption-controlled bytes enter trusted runtime state. |
| signer → stored `stablePubkey` | A signing object claims authority for an immutable room member identity. |
| live session → rotation transaction | Queued work may persist or sign after local membership retirement. |
| composite room selector → localStorage mutation | One coordinator's room operation can collide with the same room ID at another coordinator. |
| secret-bearing runtime → UI/log/test output | Private identity and decrypted material could cross into observable diagnostics or artifacts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-15-01 | Tampering | `anonymous-identity.ts`, `room-store.ts` localStorage readers | high | mitigate | Strict unknown-value/version/hex/byte validation and corrupt-present fail-closed state in this plan; Plan 15-02 applies the same policy to room records. |
| T-15-02 | Spoofing / Elevation of privilege | signer-to-`stablePubkey` attachment | high | mitigate | Plan 15-02 adds one `requireRoomSigner` guard used by host/join/resume before any send-capable session exists. |
| T-15-03 | Elevation of privilege | old in-memory session writes after rotation | high | mitigate | Plan 15-03 registers lifecycle retirement/rollback, drains or discards matching sessions before record mutation, and exposes the replacement only after completion. |
| T-15-04 | Tampering | alias migration and deletion | high | mitigate | Plan 15-02 scopes every lookup/write/delete to `(coordinatorPubkey, roomId)` and requires verified v2 read-back before alias removal. |
| T-15-05 | Information disclosure | signer, UI, logs, fixtures | high | mitigate | This plan bans secret-bearing diagnostics/artifacts, stores only the intended local record, and zeroizes retired/aborted signer buffers. |
| T-15-06 | Elevation of privilege | NIP-07/NIP-46 vs anonymous storage | high | mitigate | Separate `anonymousSigner` from remote/extension signer fields; authenticated variants never enter anonymous create/recovery/rotation code. |
| T-15-SC | Tampering | package supply chain | low | accept | No package install or upgrade exists in Phase 15; all work uses pinned project dependencies and existing browser APIs. |
</threat_model>
