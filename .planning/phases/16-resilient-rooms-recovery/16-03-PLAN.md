<decision_trace>
D-08: Coordinator transport/storage and hosted-room recovery share one terminal startup boundary.
D-09: Current-room and monotonic completed/total progress includes explicit zero-room completion.
D-10: Recoverable timeouts use bounded automatic injected retry inside startup.
D-11: Only exhausted retry is actionable failure; startup remains mounted with safe room-named diagnostics.
D-12: Shared/cancelled generation ownership prevents repeated start/restart races and stale publication.
</decision_trace>

<interfaces>
`CoordinatorStore.start()` currently owns instance lease, transport creation, startup progress, and the transition to `running`. `ChatRoomSession` owns exact room sync, lifecycle generation, persistence, and online/offline events. `HostWorkspace.restoreHostChat()` currently restores independently after transport readiness. This plan moves that restoration behind a registered typed adapter invoked by `CoordinatorStore.start()` before `running`, while preserving `requireRoomSigner` and Plan 16-01/02 composite navigation/read state.
</interfaces>
</context>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage/adapter → recovery queue | Malformed, foreign, retired, or duplicate targets must not attach or distort progress. |
| coordinator generation → async transport/session work | Old promises and timers must not mutate a later start/retry or release its resources. |
| signer/room → recovered session | Exact composite room and signer authority must be revalidated before every attachment. |
| transport/session errors → startup UI/log/tests | Internal and sensitive details must not become user diagnostics or artifacts. |
