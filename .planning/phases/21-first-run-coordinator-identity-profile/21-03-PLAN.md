<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| setup UI -> operator signer state | Identity actions must wait for the existing store's verified readiness and never create coordinator authority. |
| setup UI/autostart -> coordinator lifecycle | No lifecycle action may become available or execute before durable setup completion. |
| remote kind-0 profile -> coordinator name draft | Untrusted profile content is only an editable suggestion and must not overwrite operator input. |
| NIP-46 URI/errors -> UI/logs | Secret-bearing connection material must remain in controls and never enter status, snapshots, or logs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-12 | Elevation of Privilege | setup lifecycle gate | high | mitigate | Hide/disable every lifecycle surface, gate manual/autostart callbacks, and retain the CoordinatorStore preflight; prove with no-flash/call-count Playwright. |
| T-21-13 | Spoofing | operator/coordinator identity | high | mitigate | Reuse UserProfileStore only for human identity and assert coordinator public key remains unchanged through NIP-07/NIP-46/anonymous choices. |
| T-21-14 | Tampering | authenticated profile prefill | medium | mitigate | Accept only parsed profile strings, prioritize documented fields, keep the input editable, and guard late suggestions with local touch state. |
| T-21-15 | Information Disclosure | signer UI | high | mitigate | Never render bunker URI, relay URLs, raw errors, event JSON, full keys, or stack traces in setup status or test artifacts. |
| T-21-16 | Denial of Service | duplicate signer/save actions | medium | mitigate | Disable busy controls, keep cancellation available during NIP-46 wait, and serialize completion/publication calls. |
| T-21-17 | Repudiation | setup completion | low | mitigate | Persist the explicit marker/name atomically and prove exact reload/migration state through selectors and storage-safe assertions. |
</threat_model>
