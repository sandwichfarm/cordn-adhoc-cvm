## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → reactive preference state | User/extensions/corruption can supply arbitrary JSON and property keys. |
| composite room/participant inputs → storage key | Ambiguous identity construction could apply moderation presentation to the wrong room/person. |
| preference state → shared chat consumers | Private presentation must never enter room/wire records or sensitive artifacts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-24-06 | Tampering | local preference parser | high | mitigate | Require exact version/record shapes, own validated entries, normalized pubkeys, allowed palette names, and safe empty fallback under try/catch. |
| T-24-07 | Spoofing | ignore identity key | medium | mitigate | Reuse coordinator+room identity and add participant pubkey with an unambiguous separator; prove same-id/different-coordinator isolation. |
| T-24-08 | Information Disclosure | preference persistence | high | mitigate | Serialize only identity keys and palette symbols; unit-scan parsed record keys/values for absence of room/message/invite/key/signer material. |
| T-24-09 | Tampering | ignore/highlight boundary | medium | mitigate | Maintain separate maps and cross-map preservation tests; highlights key globally by pubkey, ignores by exact room+pubkey. |
| T-24-10 | Denial of Service | corrupt/large browser record | low | accept | Invalid entries are discarded independently and parse failure returns bounded defaults; localStorage quota failure leaves in-memory safe state without exposing data. |
