<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Bell feed to live invite capability | Safe persisted metadata is joined to an in-memory capability only at the moment of an explicit trusted action. |
| Application UI to browser permission prompt | A user gesture must cross the permission boundary; opening a dialog is not authorization. |
| Compact overlay to background workspace | Modal focus, pointer input, and dismissal cross between an active sheet and inert application content. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-06 | Elevation of Privilege | invite Accept action | high | mitigate | Resolve only trusted live invitation IDs and route through the existing same-shell redemption validator with `autojoin=1`. |
| T-18-07 | Spoofing | feed invitation presentation | high | mitigate | Render sender/room metadata from the validated ledger and require a matching live invitation ID before enabling Accept. |
| T-18-08 | Repudiation | dismiss confirmation | medium | mitigate | Require explicit inline confirmation and write the durable resolution record before removing the live invitation. |
| T-18-09 | Information Disclosure | feed and settings DOM | medium | mitigate | Render only safe ledger fields; never bind invite URLs, tokens, raw envelopes, or decrypted messages into persistent attributes or snapshots. |
| T-18-10 | Denial of Service | browser permission prompt | medium | mitigate | Make the named Enable notifications control the only prompt trigger and cover dialog open/reopen with a zero-prompt browser assertion. |
| T-18-11 | Tampering | compact modal background | low | mitigate | Apply inert background, focus trap, scrim, Escape handling, and focus return so hidden controls cannot receive accidental activation. |
</threat_model>
