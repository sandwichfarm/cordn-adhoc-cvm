<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser storage → sidebar ledger parser | Local storage is untrusted and may contain malformed, stale, duplicated, or attacker-edited favorite keys. |
| parsed encrypted chat message → invite renderer | Invite content is untrusted presentation input even after the surrounding message envelope is accepted. |
| reachability events/probes → Join availability | Asynchronous online/offline evidence may be stale or race with room/session events; non-online must fail closed for availability. |
| UI actions → navigation/local persistence | Favorite and Join controls must target exact coordinator-plus-room identities without changing membership or exposing capabilities. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-25-01 | Tampering | `parseSidebarLedger` / favorite reconciliation | medium | mitigate | Strictly accept string composite keys, deduplicate them, reconcile only against active `roomIdentityKey` values, and unit-test mixed-validity records so unrelated ledger data survives. |
| T-25-02 | Information Disclosure | `SIDEBAR_LEDGER_KEY` favorite persistence | medium | mitigate | Persist only exact composite room keys; exclude titles, coordinator origins, invite URLs/tokens, room state, decrypted content, keys, and raw errors from storage and evidence. |
| T-25-03 | Spoofing / Tampering | MessageGroup availability resolver | medium | mitigate | Resolve only the parsed invite's exact coordinator pubkey through HostWorkspace's existing local/external reachability state; unknown or absent evidence cannot enable Join. |
| T-25-04 | Denial of Service | Reachability races and failed probes | low | accept | A stale non-online result may temporarily disable a legitimate invite, but this is a reversible availability-only failure that periodic/current room evidence repairs and does not destroy data or membership. |
| T-25-05 | Elevation of Privilege | Disabled invite presentation | high | mitigate | Keep existing invite parsing, join-request, signer, and coordinator admission paths unchanged; disabled UI is never treated as an authorization control and online re-enable still calls the established autojoin flow. |
| T-25-06 | Repudiation / privacy leakage | Browser tests and diagnostics | medium | mitigate | Assert public UI/state only; do not log, snapshot, attach, or commit invite capabilities, private keys, decrypted messages, or raw transport errors. |
</threat_model>
