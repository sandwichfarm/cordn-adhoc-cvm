<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| IndexedDB record → coordinator memory | Browser-local persisted bytes are untrusted and may be corrupt, stale, or intentionally altered before restore. |
| Synchronous Cordn mutation → asynchronous writer | Cordn completes an in-memory mutation before the browser transaction commits, requiring ordered lifecycle joining. |
| Coordinator identity → IndexedDB primary key | A scope error could attach one coordinator's authority-bearing snapshot to another identity. |
| Browser storage failure → user-facing recovery | Raw exceptions and records must become static safe categories without leaking secret material. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-27-01 | Tampering | `indexedDbSnapshotStorage.ts` restore boundary | high | mitigate | Validate normalized key, schema version, envelope, and every snapshot field before restore; unit-test malformed record/version/snapshot rejection. |
| T-27-02 | Elevation of Privilege | IndexedDB record selection | high | mitigate | Use the normalized 64-hex coordinator pubkey as the sole record key, treat a missing exact key as fresh, and never auto-adopt an unscoped legacy snapshot. |
| T-27-03 | Information Disclosure | Typed storage failures and recovery UI | high | mitigate | Reduce failures to a closed category set, render only approved static copy, and assert no raw exception, key, invite, snapshot, room secret, or message reaches logs/UI/tests. |
| T-27-04 | Repudiation | Serialized mutation/stop boundary | medium | mitigate | Chain immutable snapshots in enqueue order, resolve only on transaction completion, and require successful flush before durable stop status. |
| T-27-05 | Denial of Service | Startup retry and writer failure | medium | mitigate | Use bounded user-triggered retry, generation ownership, a non-poisoned queue tail, and explicit temporary/keep-running outcomes; test that failures do not recursively restart. |
| T-27-06 | Tampering | Corrupt removal and stop-without-saving | medium | mitigate | Require native contextual confirmation, scope deletion to the active normalized key, and ensure outside tap cannot confirm destructive work. |
</threat_model>
